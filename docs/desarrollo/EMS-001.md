# EMS-001 — Diseño visual y experiencia de usuario

Estado: **COMPLETADO**  
Fecha de validación: 2026-10-12

## Alcance implementado

EMS-001 convierte el bootstrap de EMS-000 en un prototipo navegable, responsive y mobile-first. No agrega módulos de negocio ni persistencia. Todo contenido de artículos, estados y actividad se identifica como demostración.

Rutas:

| Ruta | Propósito |
|---|---|
| `/` | Inicio, buscador, ubicación, categorías, artículos recientes y llamado a publicar |
| `/explorar` | Catálogo con búsqueda y filtros locales por categoría y comuna |
| `/articulos/[slug]` | Galería, descripción, condición, ubicación aproximada y explicación del proceso |
| `/publicar` | Formulario visual; selección local de fotografías y envío no persistente |
| `/mis-cosas` | Ejemplo de publicaciones, reservas, estados y acciones no persistentes |
| `/conexion` | Desglose artículo gratis/servicio referencial y contacto protegido |

## Sistema visual

Los tokens están centralizados en `src/app/globals.css`:

| Token | Valor | Uso principal |
|---|---:|---|
| `green-deep` | `#126B5A` | acciones, marca y énfasis |
| `fresh` | `#40A88D` | acentos sobre fondos de contraste suficiente |
| `ink` | `#172D3D` | texto y fondos oscuros |
| `surface` | `#F7F8F5` | fondo cálido |
| `amber` | `#E6A75C` | avisos y acentos, no texto débil sobre blanco |

Se usa Inter con fallbacks del sistema, foco visible ámbar, objetivos táctiles de al menos 48 px, reducción de movimiento según preferencia y navegación inferior en móvil. Las variantes de botón, campo, tarjeta, etiqueta Demo y estados comparten estilos y componentes.

## Arquitectura

- `src/app` conserva la composición HTTP/UI del App Router.
- `src/components` agrupa presentación reusable por área (`layout`, `ui`, `catalog`, `listings`, `dashboard`).
- `src/shared/demo` contiene únicamente el dataset ficticio y lógica pura de filtrado, separada de React y comprobada con Vitest.
- `src/modules` y sus límites de EMS-000 no cambian; no se introducen dominio, persistencia ni dependencias de proveedores.
- Los detalles usan generación estática para los cuatro artículos ficticios.

El prototipo nunca incluye teléfono o dirección real. La vista de conexión usa caracteres enmascarados y una ubicación protegida. “Solicitar”, “Revisar publicación” y las acciones del panel muestran una confirmación explícita de que no escribieron datos. El botón de pago está deshabilitado y no existe integración de pago.


## Decisiones y riesgos pendientes

- CLP 1.000 se presenta siempre como **tarifa referencial del piloto**; falta aprobación comercial/legal definitiva.
- La ubicación se limita a comuna y sector ficticio; la política final de granularidad sigue pendiente.
- El formulario no define todavía validaciones de dominio, almacenamiento de imágenes, moderación ni límites finales.
- Autenticación, autorización, persistencia, reservas, concurrencia, pagos, webhooks y desbloqueo de contacto corresponden a tareas posteriores.
- Las fotografías generadas son adecuadas para el prototipo; antes de producción deben definirse optimización, licencias operativas y política de contenido.
