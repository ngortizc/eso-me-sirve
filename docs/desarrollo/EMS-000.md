# EMS-000 — Primer encargo para Codex

Eres desarrollador senior full-stack. Implementa únicamente el **bootstrap** de Eso Me Sirve. Antes de modificar nada lee `AGENTS.md` y los documentos en `docs/`. Prevalecen las reglas v1.1: receptor paga tras aceptación para desbloquear contacto; devolución solo si se acredita incumplimiento del publicador. **No implementar el flujo real en EMS-000.**

## Procedimiento
1. Inspeccionar el repo y herramientas; mostrar plan corto, versiones disponibles y riesgos. No borrar documentación ni sobrescribir decisiones.
2. Inicializar Next.js App Router, TypeScript strict, Tailwind, ESLint, npm con `package-lock.json` y versiones fijadas (no `latest` sin verificar). Usar `src/app` y layout mobile first accesible en español.
3. Crear la estructura modular definida en `docs/arquitectura/ARQUITECTURA.md`, documentar responsabilidades y dependencias. Sin implementar dominio real ni modelar cobros ficticios.
4. Añadir PostgreSQL en `compose.yml` para **desarrollo**, con volumen persistente, healthcheck, red adecuada, puerto publicado exclusivamente en `127.0.0.1`, secretos únicamente en `.env` ignorado y plantilla `.env.example` sin credenciales de producción.
5. Definir ORM y versión *solo si* sus migraciones reproducibles pueden verificarse; registrar la decisión en `docs/arquitectura/DECISIONES.md`. Si no, implementar readiness SQL con `pg`, documentar ORM pendiente; no crear esquemas ni migraciones ficticias.
6. Exponer GET `/api/health/live` (liveness sin DB) y GET `/api/health/ready` (verifica DB, timeout corto, HTTP 200 / 503, no divulga secretos).
7. Portada en español con marca Eso Me Sirve, propuesta de valor y estados vacíos inequívocos. Elementos que no funcionan deben marcarse como demostración o quedar fuera.
8. Añadir manifest PWA, iconos propios o placeholders identificados y comportamiento de instalación donde se soporte. No cachear respuestas autenticadas, pagos, contacto, reservas o webhooks; no ofrecer uso offline de transacciones.
9. Crear Dockerfile multi-stage `output: 'standalone'`, `.dockerignore` y ejemplo de configuración productiva con Caddy/HTTPS sin desplegar recursos reales. Contenedor no-root.
10. Integrar Vitest (prueba unitaria), Playwright (smoke móvil/escritorio + endpoint) y GitHub Actions para `npm ci`, lint, typecheck, test y build. Aclarar dependencias externas de CI/DB y levantar servicios cuando corresponda.
11. Documentar instalación y ejecución en Windows con WSL2 y en Linux; documentar configuración, comandos y troubleshooting. No suponer que Windows PowerShell equivale a bash.
12. Ejecutar realmente pruebas, compilación y servicios necesarios. Si entorno impide ejecución, reportar bloqueo exacto y **no** declarar éxito.

## Criterios de aceptación
- `npm ci`, `npm run lint`, `npm run typecheck`, `npm run test`, `npm run build` funcionan en entorno reproducible.
- `docker compose up -d db` levanta PostgreSQL; readiness 200 con conexión y 503 sin DB, sin filtrar credenciales.
- Página inicial responsive verificable con Playwright y contenido sin datos ficticios de personas/productos.
- PWA manifest válido. CI configurado. No hay secretos en Git ni puertos públicos de PostgreSQL.
- README, AGENTS, ADR, `.env.example`, Dockerfile, Compose, pruebas y script ejecutables.
- Entregar listado de archivos cambiados, versiones instaladas, comandos ejecutados con resultados, capturas/evidencias si se puede, pendientes y propuesta EMS-001.

## Límites
No pagar, reembolsar, registrar usuarios reales, publicar productos reales, enviar correo real, enviar datos de contacto ni ejecutar despliegue productivo. No hacer push ni commits remotos sin autorización. No construir funcionalidades extra fuera de alcance.
