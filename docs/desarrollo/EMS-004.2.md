## Mejoras visuales

`/mis-cosas` conserva los datos servidor de EMS-004 y los presenta con un encabezado compacto, tres contadores reales y pestañas accesibles para publicaciones, solicitudes enviadas y solicitudes recibidas. Las teclas izquierda/derecha, Inicio y Fin cambian la pestaña y el foco. «Pendiente de ti» aparece únicamente cuando existen solicitudes recibidas `PENDING` o reservas propias `PENDING_PAYMENT`.

Las tarjetas muestran fotografía principal cuando el actor todavía está autorizado, título, estado, fecha y acción pertinente. Si una fotografía ya no es accesible se usa un estado visual neutro, no una URL alternativa insegura. Solicitudes, reservas e historial mantienen los DTO mínimos de EMS-004. La consulta de fotografías permite al receptor de una reserva `RESERVED` leer la imagen del artículo con respuesta privada `no-store`; terceros y publicaciones `REMOVED` conservan las restricciones anteriores.

El detalle del artículo explica que el bien es gratis y que, tras la aceptación, existen 24 horas para pagar el servicio. La confirmación de solicitud aclara que aún no corresponde pagar. La reserva muestra `PENDING_PAYMENT`, tarifa, vencimiento exacto en Chile, cuenta regresiva informativa, consecuencia del vencimiento y pago deshabilitado. PostgreSQL continúa siendo la autoridad temporal.

La tarifa del piloto permanece centralizada en `CONNECTION_SERVICE_FEE_CLP`; las vistas usan el valor del dominio o el snapshot del DTO y `formatClp`. No se añadió proveedor, checkout, webhook, `PAID` ni contacto.

## Usuarios locales de prueba

`npm run dev:seed-users` crea o rota tres cuentas sintéticas verificadas:

- `publicador-a@users.eso-me-sirve.test` — Publicador A.
- `receptor-b@users.eso-me-sirve.test` — Receptor B.
- `receptor-c@users.eso-me-sirve.test` — Receptor C.

El comando exige `APP_ENV=development`, `NODE_ENV` distinto de producción, PostgreSQL y URL de autenticación en loopback. Usa `signUpEmail`, `verifyEmail`, `requestPasswordReset` y `resetPassword` de Better Auth; no escribe hashes manualmente. La repetición no duplica cuentas: regenera las contraseñas y revoca sesiones previas mediante el flujo oficial de restablecimiento. Rechaza modificar una cuenta reservada cuyo nombre o rol no coincida con el perfil sintético esperado.

Las contraseñas tienen entropía criptográfica, nunca se imprimen y se guardan en `.data/dev-seed-users.json`, ignorado por Git. El archivo se crea con modo `0600`; en Windows también elimina herencia ACL y concede acceso solo al usuario ejecutor. Para regenerar credenciales, repetir el comando y volver a leer el archivo local. Ninguna cuenta recibe rol `ADMIN` y el sembrador no crea publicaciones ni solicitudes por SQL: los escenarios manuales usan la aplicación para conservar reglas y auditoría.

La ejecución real creó tres cuentas; una segunda ejecución confirmó rotación sin duplicados. PostgreSQL mostró exactamente tres filas `.test`, verificadas y con rol `USER`. Las credenciales concretas no se incluyen en este documento.

## Riesgos y decisiones pendientes

- El pago y contacto continúan deliberadamente deshabilitados hasta EMS-005, proveedor y revisión legal.
- La cuenta regresiva es informativa; solo las operaciones servidor y el worker vencen reservas.
- La foto privada de una reserva se autoriza por participante; no concede acceso a contacto ni a archivos retirados.
- El archivo de credenciales es apto para desarrollo local, no para compartir ni reutilizar en CI/producción.
- El sembrador no crea datos de negocio para evitar estados artificiales y bypass de auditoría.
